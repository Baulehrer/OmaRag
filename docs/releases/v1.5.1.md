# OmaRag 1.5.1 — indexing works again

If you installed 1.5.0, adding a book failed after about twenty seconds with a
message about huggingface.co. This release fixes that. Two separate faults caused
it, and `omarag-cli doctor` reported READY through both of them.

## Books could not be indexed

OmaRag keeps its models in its own cache and runs the import in an offline
worker, so everything it needs must be downloaded beforehand. Three things never
were: the two models that read page layout and tables, and the tokenizer that
decides where a chunk ends. The import therefore failed at the first page.

Reranking was broken in a related way. The model was fully downloaded, but
recorded under its version number instead of its name — and everything looks it
up by name. So the one model that had already been downloaded could not be found
either.

Both are fixed, and an existing installation is repaired on the spot; nothing
needs downloading twice.

## Conversion aborted on some installations

On a machine whose OmaRag folder has a space in its path, or that has no C++
compiler, the layout model failed to start and every document was reported as
unreadable. It now falls back to a slower but working mode.

## Doctor no longer claims to be ready when it is not

Answering questions and adding books can fail independently: OmaRag could serve
questions while being unable to index a single page, and still report READY.
`omarag-cli doctor` now has its own **Indexing** line that names any missing
model.

## Upgrade

```bash
omarag-update
```

Existing libraries, books and settings are preserved. Nothing needs reindexing —
but if an import failed under 1.5.0, add the book again.
