# OmaRag 1.5.0 — a new look, and libraries that actually get created

This release rebuilds the interface, adds 36 colour themes, and fixes a bug that made creating a
library appear to fail. Answers remain bound to verifiable source passages; nothing about how books
are indexed or answered has changed in a way that requires reindexing.

## Fixed: creating a library looked broken

Creating a library reported an error even though the backend had created it. Pressing Enter again
made another one, so a single attempt could leave a dozen duplicates behind.

The cause was a contract mismatch: the backend sends `privacy_mode: "device-only"`, and the client
only understood `local` and `cloud-allowed`. The whole workspace manifest therefore failed to
parse, and a successful creation was reported as a failure. The client now understands every value
the backend sends, including the legacy spellings, and a test parses a real response so the two
sides cannot drift apart again.

If you have duplicate libraries from an earlier version, delete them in **Libraries** (`Ctrl+L`).

## Adding books without a library

Pressing `I` with no library no longer opens a file browser that has nowhere to import into. It
asks for a library name first and then continues to the import by itself.

## Appearance

- **36 colour themes**, imported from superfile and Omarchy. Where both ship the same scheme, the
  Omarchy variant is used.
- The *Omarchy System* theme follows your desktop live.
- **Your own themes**: drop a `.toml` into `~/.config/omarag/themes/`. A theme with the same name as
  a bundled one replaces it. A broken file is skipped and reported, never fatal.
- Every region — navigation, workspace, evidence, dialogs — carries its own border and selection
  colour, so the panels read apart instead of sharing one accent.
- Some upstream themes ship an idle border almost invisible against their own background, or a
  selection fill equal to it. Both are corrected on import, so no theme can hide the region
  boundaries or the selected row.

Themes are selected by name now, so your choice survives the theme list changing.

## Interface

- Rounded frames with the title cut into the top edge and status into the bottom.
- **Progress bars** with a colour gradient for indexing, model downloads, and machine load. Work
  whose extent the backend cannot report gets a moving indicator rather than an invented
  percentage.
- The indexing screen shows the **real** pipeline phases and highlights the running one. It
  previously showed a fixed sequence that matched nothing the backend reported.
- Indexing rows now show the page range and estimate the backend already produced.
- **Icons** are configurable under Settings › Appearance: full, restrained, or off, with Nerd Font,
  Unicode, or ASCII glyphs.
- Cited pages and figures beyond the fourth are reachable — the evidence grid pages around the
  selection instead of hiding the rest.
- Answers stream as you read: prose appears while the model is still writing, set in italics until
  the claim it belongs to has been checked against its sources, then replaced by the verified text.

## Speed

- Publishing a book no longer blocks the daemon. It ran on the event loop with one insert per
  chunk — thousands for a textbook — so health, events, and every other request stalled until it
  finished. It now runs off the loop and inserts in one batch.
- Looking up a single book was loading and parsing the entire library; it is now a direct lookup
  (measured 79× faster with 120 books).
- Conversions may overlap when memory clearly allows it. Questions keep absolute priority, and the
  limit drops back to one under memory pressure.

## Naming

The interface, CLI, and API description no longer carry the retired second name. On-disk paths and
configuration keys are unchanged, so existing libraries keep working untouched.

## Upgrade

```bash
omarag-update
```

No reindexing is required. Existing libraries, books, and settings are preserved.
