# OmaRag 1.2.0 — faster, focused, and storage-aware

OmaRag 1.2 improves textbook search without silently rebuilding existing libraries. Answers remain
bound to verifiable source passages.

## Highlights

- New books can use Book Index V3. Page-range overlap keeps boundary evidence intact without
  creating duplicate entries.
- Contents, indexes, and similar registers remain primary structure sources. A bounded local
  fallback may select only existing headings and page references; it cannot invent content.
- Prose, tables, formulas, figures, and navigation are identified separately. Only unchanged book
  evidence may support an answer.
- Related searches are batched and expanded only when evidence is missing. Fast, Normal, and
  Quality keep their adaptive budgets.
- Answers can include exact support spans plus honest calibration and verification status. Missing
  verification is never presented as confidence.
- RAG and analysis use the same source-bound path. Normal and Explore cannot add unsupported model
  knowledge. `verifier=off` requires an explicitly configured expert workspace.
- The inspector shows cited pages and up to four relevant figures or tables. Expensive media work is
  lazy, and unreferenced derived files can be cleaned safely.
- Bounded caches are compressed. New Book V3 references do not expose absolute local file paths.
- Device-only mode blocks content-bearing requests to external destinations. LAN and cloud access
  require separate, visible permission.
- New workspaces use limited retention. Existing workspaces keep unlimited history until retention
  is enabled. Cleanup always requires a current preflight and confirmation.
- Pinned runs, jobs, and backups survive cleanup. At most three unpinned backups are retained.
- Permanent book deletion requires a generation- and fingerprint-bound 15-minute preflight.
  Backups require separate confirmation, while pinned provenance blocks deletion. New backups pair
  files with the workspace's SQLite generation catalog for consistent restore.
- Paused indexing no longer holds the global writer lease.
- Launchers, services, desktop files, configuration paths, container storage, and update commands
  now use the `omarag` name. The retired pre-SOAP TUI backup is no longer shipped.
- The local models actually used are verified before answers and cache hits. Results are discarded
  if a model changes during the request. Frequently used models may remain warm for up to five
  minutes and are released immediately under memory pressure.

## Safe upgrades

- Existing indexes remain readable.
- A full V1.2 rebuild is optional and starts only after preflight and explicit confirmation.
- If a profile changes the embedder, plain `APPLY` is rejected. `APPLY_AND_REINDEX` first installs
  and verifies every pinned model, then stages the local configuration with `0600` permissions. The
  old index and configuration remain usable until the maintenance boundary. From that point, the
  configuration and rebuild move together. Failure leaves the workspace locked but resumable; it
  never serves old vectors with the new embedder.
- Books and models are never downloaded silently.

## Known limits

- The private 300-case editorial gold set is not included. This release does not claim a universal
  quality gain from that set, although the evaluation and digest framework is present.
- No production-selected NLI verifier model is bundled. The interface and fail-closed behavior are
  implemented: in automatic mode, risky numeric, negation, comparison, table, formula, and
  multi-source claims are rejected without a suitable verifier. Only visible Expert mode with
  `verifier=off` can disable this extra gate.
- Visual Dense has an experimental index contract but fails closed until its media-quality gate
  passes. Late Chunking also remains experimental and is not part of the production path.
- OmaRag 1.2 finds formulas, variables, and table values but does not perform domain calculations.
- User-attached images cannot be used as new question sources until they meet the same
  generation-bound evidence and claim checks as book crops. Cited pages and up to four real book
  crops are unaffected.
- The packaged target remains Linux x86-64.
