# OmaRag 1.0.0 — Fast Feedback, Calm Control

OmaRag 1.0 turns the terminal workbench into a more legible, responsive instrument without
changing Vanilla Haiku RAG. Work now reports what it is actually doing, background resources
adapt to the machine, and evidence remains cheap until it is inspected.

## Highlights

- Metis and Aletheia show the real answer or indexing phase, measured progress and a conservative
  ETA range instead of a generic busy animation.
- Chat can target all books or one selected book. First-run guidance leads directly from an empty
  library to indexing and then to the first question.
- A short typing pause can warm configured models only when memory is healthy and no foreground
  job is active. This is opportunistic and never delays the user's action.
- Query-worker residency adapts from 120 seconds to 30 seconds or immediate release as memory
  pressure rises. Idle TUI redraws fall to one every two seconds.
- Citation metadata travels with the answer, while expensive layout anchors and rendered page
  previews are resolved only for the selected evidence.
- The Source inspector distinguishes related figures from page evidence and uses one, two or four
  deliberate tiles without empty placeholders.
- Library rows use stored page and byte metadata; opening the library no longer re-hashes every
  PDF or starts one `pdfinfo` process per book.
- `oracle-cli doctor` checks the API, component versions, Haiku availability, models, memory,
  workspace permissions and cgroup support, with JSON output for automation.

## Managed originals

OmaRag still retains an immutable managed original. It is required for stable page citations,
previews and recovery when the imported file is renamed, edited or removed. On a compatible
filesystem the archive is a copy-on-write reflink, so unchanged blocks do not consume a second
physical copy. Other filesystems use one streaming pass that copies and computes SHA-256 together.
Hardlinks are deliberately excluded because later edits to the user's file would silently alter
the indexed evidence. Book details report this as a space-saving clone, managed copy or reused
managed original.

## Compatibility

- Existing workspaces and managed originals remain valid; no re-index is required.
- API changes are additive within `/v1`. Older clients ignore the additional phase, runtime and
  receipt fields.
- The `oracle` launcher and existing data/configuration paths remain stable.
- Vanilla Haiku RAG remains unmodified behind its public compatibility gate.
- Linux x86_64 remains the packaged target.

## Release gates

- Rust formatting, Clippy with warnings denied and the complete Rust test suite.
- Ruff formatting/linting and the complete non-environmental Python test suite.
- Regenerated OpenAPI, event and workspace schemas with contract-drift tests.
- Release builds for the native client, daemon wheel and portable AppImage.
